# Release round A — a stranger's first run, and their data (1.0.1)

25–26 September 2026, branch `fb/rel-a` on top of build 109. The **release** build (`WingFoil
Release`, no flags) on a fresh simulator (`rel-a`, iPhone 17 Pro, iOS 26.5, deleted
afterwards), plus the kit's own tests for everything a simulator cannot tap.

Severity: **blocker** (must not ship), **fix** (should be fixed before or with 1.0.1), **note**
(worth knowing, no action needed now). Fixed in this round: F-1, F-2.

## Findings

| # | severity | where | finding | state |
|---|---|---|---|---|
| F-1 | **blocker** | `ios/project.yml`, `WingFoilRelease` | The release target still carried `MARKETING_VERSION: "1.0.0"` of its own, while every other target is on 1.0.1. The 1.0.1 archive would have gone up as 1.0.0 again, and Settings → About read *1.0.0 (109)* on the simulator. The comment above it still described the old two-line scheme (release 1.0.x, beta 0.x). `tools/check_release.py` let it through because it allowed a release line of its own. | **fixed**: the override is gone, so the release inherits 1.0.1. The release check now fails a release target that stamps a version the others do not; `docs/engineering.md` and the `tag-ios` comment in the Makefile now say the same |
| F-2 | **fix** | kit, `SessionIngestor.reanalyze` | A re-analysis wrote back the **whole row it was handed**. `reanalyzeStale()` reads every row once and then works through them one by one (after an engine bump, that is the whole library at launch), and *Re-run analysis* hands over the list the screen was showing. A rename, a rider or a caption changed while that ran was overwritten with the old value. Gear was safe because it lives in `session_gear`. | **fixed**: the write re-reads the row inside the transaction and changes only the derived columns. A session deleted during the sweep stays deleted, with nothing written for it. Test: `LibraryTests.reanalysisFromAnOldSnapshotKeepsTheRidersEdits` |
| F-3 | note | first run, all doors | What a stranger sees, in order: the launch mark, then the splash, then **What CleanJibe does** (tagline, the paragraph, the track and its legend, *Try the example session*, the card). The Import sheet has **three doors**: intervals.icu (*Set up in Settings → intervals.icu*), Files (*FIT or ZIP…*) and Strava (*Set up in Settings → Strava*, with the Compatible-with-Strava mark). There is **no Apple Health door**, no Apple Watch app door and no dedicated Garmin ZIP button, which matches `docs/channels.md`. Settings shows the key field with *Save & check* greyed out until a key is typed, *Get a key in 4 steps*, *Sync not working?*, *Connect with Strava*, the Notifications switch with its "add your key first" line, *Coming in a future release*, Storage, and Library backup. No beta or dev door showed anywhere: no Beta section, no Apple Health section, no windsurf, no tuning, no Garmin link. `make release-check BINARY=…` passes, including the `strings` check on the release binary | — |
| F-4 | note | intervals.icu / Strava | I stopped at the key screen because `lab/.env` holds Jan's real intervals.icu key, not a test key. For Strava I only looked at the connect screen; *Connect with Strava* was not tapped. Apple Health has no door in the release (it is a beta feature), so it has no empty state or permission path to check | — |
| F-5 | fix (Jan decides the rule) | kit, dedupe key | **One afternoon can land twice through Strava.** The FIT's span runs from its first record to its last. Strava's copy runs from its first fix to its last (`StravaImport` drops points with no position). When a watch keeps recording without GPS for more than a minute after the ride (left running in the van), the two-sided ±60 s duration check sees two different sessions. The first FIT in the corpus (13 June 2026) has 43 minutes of records with no position after its last fix: FIT span 10 338 s against Strava's 7 742 s. The start matches within 8 s. The usual case (fixes that cover the records) dedupes correctly across file, intervals.icu and Strava. Impact today is small, since Strava is capped at 10 riders. Possible fixes: take the FIT's span from its fixes, or compare durations one-sided the way tombstones already do. The catch with one-sided: a friend's session that starts within the same minute would merge into yours. | held as a known issue: `StravaImportTests.aFitWithAPositionlessTailIsNotYetMatchedToItsStravaCopy` (`withKnownIssue`, so it fails the day the rule changes) |
| F-6 | note (Jan decides) | kit, dedupe order | A Strava-only row (class c: positions only, records uncertified) does **not** give way when the FIT of the same afternoon arrives later through intervals.icu or a file. It stays class c with uncertified records, and only the provenance merges. `SessionIngestor.yields` only lets a direct-transfer row give way. A rider who connects Strava first and intervals.icu second keeps the weaker copy of every overlapping session | open question 2 |
| F-7 | note (Jan decides) | Files door, Garmin export ZIP | Tombstones are only checked by the intervals.icu and Strava syncs. A hand-picked FIT bringing a deleted session back is intended. But a **Garmin export ZIP** (release since 14 Sep) is hundreds of sessions picked at once, and it brings back every session the rider deleted | open question 3 |
| F-8 | note | Import sheet footers | The recording class is shown as rider text: "Class A · Garmin watch app or Class B · any speed-certified file", "Class C · positions only". `docs/voice.md` rule 11 lists *class (b)* as an IT word. It is on the screen on purpose (pattern H, the class as a label), so the two documents disagree | open question 4 |
| F-9 | note | Settings → Library backup | With an empty library, *Back up library* is disabled with no reason given, which is pattern G (a disabled control with nothing said). Storage reads "FIT archive · Zero KB", which is the system formatter's wording. Both are harmless | — |
| F-10 | note | simulator limits | `simctl` cannot tap. Not driven here: the welcome cover's lower half (the family, *Join the beta*, Support), the empty library behind the cover, the Files picker, the rider prompt, and the backup/restore file pickers. The import path was driven with `UI_IMPORT_FIXTURES=1` (the list after it is correct, and the welcome is gone on the next launch). The empty library and the pickers need one pass by hand on a phone | — |
